# Дизайн-система CleanLink

Источники: `docs/01-spec.md`, `docs/02-ux.md`. Токены в машиночитаемом виде — в
`docs/tokens/colors.json`, `docs/tokens/design-tokens.css`, `docs/tokens/tailwind.tokens.js`.
Ни один компонент фронтенда не должен использовать хардкод-hex — только `var(--color-*)` /
Tailwind-классы, ссылающиеся на эти переменные.

---

## 1. Визуальное направление

CleanLink — агрегатор-маркетплейс («Aviasales для клининга»): пользователь **сравнивает**
компании по цене, рейтингу и отзывам и **принимает решение о заказе за деньги**. Это не
творческий продукт и не чистый финтех, а *инструмент сравнения и оформления сделки* — поэтому
направление выбрано **нейтрально-функциональное с элементами доверия/финансовой строгости**:

- Плотная информационная сетка (карточки компаний, таблицы заказов, статистика) — данные должны
  считываться быстро, без лишнего декора, как в агрегаторах билетов/отелей.
- Один явный акцентный цвет на тему используется экономно: главные CTA («Заказать», «Создать
  аккаунт», «Подтвердить»), активные состояния навигации, ссылки, фокус-кольцо. Весь остальной
  интерфейс — нейтральные фон/поверхность/текст, чтобы акцент не терялся среди прочих цветных
  элементов.
- Статусы (заказ, верификация, акции) кодируются устойчивой семантической палитрой
  (success/warning/error/info/neutral), одинаковой логики во всех трёх темах — это создаёт
  ощущение надёжности сервиса, через который проходят реальные деньги и обязательства между
  клиентом и компанией.
- Три темы — не редизайн, а три *настроения одного и того же интерфейса*: «Тёмная» для
  комфортной работы вечером/в кабинете компании со статистикой, «Светлая с градиентом» —
  чуть более тёплая и «человечная» витрина для гостя/клиента на этапе выбора компании,
  «Классика» — строгий вариант для тех, кто хочет минимум визуального шума (аналог
  светлой темы делового приложения).

Продукт — единственный язык интерфейса русский, поэтому шрифт обязан иметь качественную
кириллицу (см. раздел 4).

## 2. Токены — где искать

| Файл | Назначение |
|---|---|
| `docs/tokens/colors.json` | Полный набор значений (спейсинг, радиусы, типографика, motion, палитры трёх тем) в JSON — источник для генерации/импорта в `tailwind.config` любым способом (JS require, скрипт-конвертер, etc). |
| `docs/tokens/design-tokens.css` | Готовые CSS custom properties: `:root` (дефолт = classic), `@media (prefers-color-scheme: dark)` (страховка на первый кадр), `:root[data-theme="dark|gradient|classic"]` (явный выбор пользователя). Плюс сброс, базовая типографика, утилиты фокуса, классы анимаций/скелетонов. Подключается в `globals.css` проекта через `@import` или копируется как есть. |
| `docs/tokens/tailwind.tokens.js` | Готовый объект для `theme.extend` в `tailwind.config` — все Tailwind-классы (`bg-accent`, `text-secondary`, `rounded-lg`, `duration-fast`...) резолвятся в CSS-переменные, поэтому смена `data-theme` не требует пересборки. |

Архитектор на следующем шаге просто импортирует `tailwind.tokens.js` в `theme.extend` и кладёт
`design-tokens.css` в `src/styles/tokens.css` (первым импортом в `globals.css`, до Tailwind
base/utilities).

## 3. Палитра — три темы

Названия тем в коде (`data-theme`): `dark`, `gradient`, `classic`. Заданные пользователем цвета
сохранены буквально (фон, карточки, акцент/градиент) — остальные токены выведены из них так,
чтобы держать контраст ≥ 4.5:1 для обычного текста и ≥ 3:1 для крупного текста/границ
интерактивных элементов. Формула контраста — WCAG relative luminance, ключевые пары посчитаны
вручную ниже.

### 3.1. Тема «Тёмная» (`dark`)

| Токен | Значение | Назначение |
|---|---|---|
| `--color-bg` | `#0a0a0f` | фон приложения (задан пользователем) |
| `--color-surface` | `#1a1a2e` | карточки, панели (задан пользователем) |
| `--color-surface-elevated` | `#22223d` | модалки, дропдауны, тултипы |
| `--color-surface-hover` | `#202038` | hover строки таблицы/списка |
| `--color-border` | `#2a2a45` | тонкие разделители, hairline |
| `--color-border-strong` | `#3a3a5c` | границы полей ввода, активные разделители |
| `--color-text-primary` | `#f5f4fb` | основной текст |
| `--color-text-secondary` | `#a8a7c2` | вторичный текст, подписи, плейсхолдеры |
| `--color-text-disabled` | `#6f6e8a` | заблокированный текст/иконки |
| `--color-accent` | `#6c63ff` | бренд-акцент (задан пользователем): ссылки, иконки, границы выбранных элементов, фокус-кольцо, вкладки |
| `--color-accent-600` | `#5951e8` | заливка primary-кнопки (см. врезку ниже) |
| `--color-accent-700` | `#4a41d6` | hover primary-кнопки |
| `--color-accent-800` | `#3830a3` | active/pressed primary-кнопки |
| `--color-accent-subtle` | `rgba(108,99,255,.16)` | подложка выбранной вкладки/чипа |
| `--color-success` | `#34d399` | статус «Выполнен», позитивные значения статистики |
| `--color-warning` | `#fbbf24` | статус «В работе», предупреждения, звёзды рейтинга |
| `--color-error` | `#f87171` | ошибки форм, деструктивные действия |
| `--color-info` | `#60a5fa` | статус заказа «Создан» |
| `--color-neutral` | `#a8a7c2` | статус «Отменён» (намеренно нейтральный, не «ошибка») |
| `--color-overlay` | `rgba(5,5,10,.72)` | подложка модалки |

**Проверка контраста (относительная яркость WCAG):**
- `text-primary` (#f5f4fb) на `bg` (#0a0a0f) → **18.1 : 1**
- `text-secondary` (#a8a7c2) на `bg` → **8.4 : 1**; на `surface` (#1a1a2e) → **7.3 : 1**
- `accent` (#6c63ff) на `bg` → **4.6 : 1** (проходит как крупный/графический элемент — иконки,
  границы, текст ссылок ≥ 16px medium)
- белый текст на `accent-600` (#5951e8) → **5.6 : 1** (кнопка); на `accent-700` (#4a41d6) →
  **7.0 : 1** (hover)
- `success` на `bg` → 10.3:1; `warning` на `bg` → 11.8:1; `error` на `bg` → 7.1:1; `info` на
  `bg` → 7.8:1 — все статусные цвета читаемы и как текст, и как иконки.

> **Почему `accent` и `accent-600` — разные значения, а не нарушение правила «один акцентный
> цвет».** Буквальный акцент пользователя `#6c63ff` даёт лишь 4.3:1 для белого текста на своей
> заливке — недостаточно для обычного текста 14–16px по AA. Поэтому `#6c63ff` остаётся *лицом
> бренда* (ссылки, иконки, фокус-кольцо, обводки — везде, где это не заливка под мелким белым
> текстом), а сплошная заливка primary-кнопки берёт на 1 тон темнее (`accent-600`) того же
> оттенка — это один и тот же акцентный цвет, а не второй оттенок, ровно так же, как Tailwind
> использует `indigo-600` для кнопки при бренд-цвете `indigo-500`.

кладутся на градиент только с `text-shadow` или полупрозрачной тёмной подложкой
(`rgba(36,31,56,.35)` + `blur`), либо градиент используется только как декоративная кайма/фон
карточки, а текст — на непрозрачном `--color-surface` поверх него (так и решено для карточки
компании и карточки акции, см. раздел 6).

## 4. Типографика

- **Шрифт:** `Inter` — одна гарнитура для заголовков и текста (для инструмента сравнения не
  нужна декоративная вторая пара, лишний шрифт — источник хаоса). Хорошая поддержка кириллицы,
  чёткие цифры (важно: цены, рейтинги, проценты скидок, номера заказов).
  Подключение с одного разрешённого CDN (Google Fonts) с системным запасным стеком:
  ```
  font-family: 'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto,
    'Helvetica Neue', Arial, sans-serif;
  ```
  Если фронтенд-инженер решит не тянуть внешний CDN (офлайн-сборка/CSP) — запасной стек уже
  визуально близок к Inter (Segoe UI/Roboto — те же пропорции), деградация не критична.
- **Шкала размеров (6 значений):** `xs` 12px / `sm` 14px / `base` 16px / `lg` 20px / `xl` 24px /
  `2xl` 32px.
  - `2xl` — H1 (заголовок главного экрана, суммы статистики)
  - `xl` — H2 (заголовки разделов «ТОП-3», «Все компании»)
  - `lg` — H3 (название компании в карточке, заголовки модалок)
  - `base` — тело текста, лейблы кнопок
  - `sm` — вторичный текст, подписи полей, таймстемпы
  - `xs` — бейджи, метки, подписи под иконками
- **Начертания:** 400 (текст), 500 (лейблы полей, вторичные кнопки), 600 (кнопки, заголовки
  карточек, активные табы), 700 (H1/H2).
- **Межстрочный интервал:** 1.2 (заголовки), 1.5 (интерфейсный текст), 1.6 (длинные тексты —
  описание компании, текст отзыва).
- **Числа/цены:** табличные цифры (`font-variant-numeric: tabular-nums`) в таблицах заказов и
  статистики, чтобы колонки цен не «прыгали».

## 5. Сетка отступов, радиусы, тени

**Отступы (8 значений):** `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64` px (`--space-1` … `--space-8`).
Внутренние отступы компонентов — из `space-2`…`space-5`, отступы между секциями страницы —
`space-6`…`space-8`.

**Радиусы:** `sm` 6px (инпуты, мелкие чипы) / `md` 10px (кнопки, поля) / `lg` 16px (карточки) /
`xl` 20px (модалки, герой-блок) / `full` 999px (аватары, пилюли-бейджи, таб-переключатели).

**Тени** — заданы отдельно на тему (тёмная тема требует более непрозрачных чёрных теней, светлые
— мягких нейтральных):
- `shadow-sm` — hover карточки в списке
- `shadow-md` — карточка ТОП-3, поднятые элементы
- `shadow-lg` — модальные окна, выпадающие меню

## 6. Анимации (спецификация для Framer Motion)

Заданные пользователем параметры зафиксированы как токены и обязательны для всех интерактивных
элементов уровня «кнопка/карточка/чип»:

| Параметр | Значение | Токен |
|---|---|---|
| Hover-масштаб | `scale: 1.05` | `--scale-hover` |
| Active/pressed-масштаб | `scale: 0.95` | `--scale-active` |
| Длительность | `150ms` | `--duration-fast` |
| Плавность | `cubic-bezier(0.4, 0, 0.2, 1)` (стандартный ease-out-ish, ощущается отзывчиво без «резины») | `--easing-standard` |

**Framer Motion variants (референс для фронтенд-инженера):**
```js
export const pressable = {
  rest: { scale: 1 },
  hover: { scale: 1.05, transition: { duration: 0.15, ease: [0.4, 0, 0.2, 1] } },
  tap: { scale: 0.95, transition: { duration: 0.15, ease: [0.4, 0, 0.2, 1] } },
};
```
Применяется к: primary/secondary/danger-кнопкам, кликабельным карточкам компаний (в списке и в
ТОП-3), чипам городов, иконкам в шапке («сердце», тема, колокольчик), звёздам рейтинга при вводе
оценки в форме отзыва. **Не** применяется к строкам таблиц заказов/услуг (там только смена
`background-color`, чтобы не создавать «прыгающий» плотный список) и к самим карточкам во время
скролл-появления (см. ниже — это отдельная анимация).

**Переходы страниц — fade + slide:**
```js
export const pageTransition = {
  initial: { opacity: 0, y: 8 },
  animate: { opacity: 1, y: 0, transition: { duration: 0.2, ease: [0.4, 0, 0.2, 1] } },
  exit: { opacity: 0, y: -8, transition: { duration: 0.15, ease: [0.4, 0, 0.2, 1] } },
};
```
Оборачивает контент маршрута (`<AnimatePresence mode="wait">` вокруг `<motion.main>`), не
затрагивает фиксированную шапку/сайдбар/таб-бар — они не должны «уезжать» при каждой навигации.

**Scroll-reveal через Intersection Observer:**
- Применяется на главном экране (герой → поле поиска → чипсы городов), на экране города
  (карточки ТОП-3 и список компаний появляются по очереди, `stagger: 40ms`), на карточке
  компании (блоки контента вкладок при первом рендере).
- CSS-реализация (не требует Framer Motion, дешевле для длинных списков): класс `.scroll-reveal`
  + JS-хук на `IntersectionObserver` с `threshold: 0.15`, при пересечении добавляется класс
  `.is-visible` (см. `docs/tokens/design-tokens.css`, готовые классы).
- Framer Motion-эквивалент для элементов, которым нужен более богатый вход (карточка ТОП-3):
  ```js
  export const revealOnScroll = {
    hidden: { opacity: 0, y: 16 },
    visible: (i = 0) => ({
      opacity: 1,
      y: 0,
      transition: { duration: 0.25, delay: i * 0.04, ease: [0.4, 0, 0.2, 1] },
    }),
  };
  // <motion.div variants={revealOnScroll} initial="hidden" whileInView="visible"
  //   viewport={{ once: true, amount: 0.15 }} custom={index} />
  ```
- Правило: анимация «один раз» (`once: true`) — при повторном скролле вверх-вниз карточки не
  должны мигать заново, это раздражает в длинном списке из 12+ карточек.

**`prefers-reduced-motion`:** все три вида анимаций (hover/active-scale, переходы страниц,
scroll-reveal) при включённой настройке ОС/браузера сводятся к мгновенной смене `opacity` без
`transform` — реализовано глобально в `design-tokens.css` через `@media (prefers-reduced-motion:
reduce)`, во Framer Motion — через хук `useReducedMotion()` c условной заменой variants на
`{ opacity: 0 } → { opacity: 1 }` без `y`/`scale`.

## 7. Анатомия базовых компонентов

Везде: цвет — только через `var(--color-*)`; hover/active — только `.interactive-scale`/Framer
`pressable` variants там, где элемент кликабелен целиком (кнопка, карточка-ссылка, чип), не там,
где кликабелен только дочерний элемент (например, строка таблицы с отдельной кнопкой действия).

### 7.1. Кнопка

Варианты: **primary** (заливка `accent-600`, текст `accent-contrast`), **secondary** (заливка
`surface`, граница `border-strong`, текст `text-primary`), **ghost** (без фона/границы, текст
`accent`, фон `accent-subtle` на hover), **danger** (заливка `error`, текст белый — используется
только в подтверждении удаления/отмены заказа).

Размеры: `sm` (высота 32px, паддинг `space-2 space-3`, `text-sm`), `md` (высота 40px, паддинг
`space-3 space-4`, `text-base` — дефолт), `lg` (высота 48px, паддинг `space-3 space-5`, `text-lg`
— главные CTA типа «Создать аккаунт», «Заказать» в модалке подтверждения).

Радиус `radius-md`. Состояния:
- **default** — заливка/граница по варианту.
- **hover** — `scale(1.05)` + для primary заливка темнеет до `accent-700`, для ghost — фон
  `accent-subtle`.
- **active** — `scale(0.95)`, для primary заливка `accent-800`.
- **focus-visible** — `outline: 2px solid var(--color-focus-ring)`, `outline-offset: 2px` (не
  зависит от варианта кнопки).
- **loading** — спиннер 16px слева от текста, текст меняется на процессный («Создаём аккаунт…»,
  «Входим…», «Сохраняем…» — см. `02-ux.md`), кнопка `pointer-events: none`, hover/active-scale
  отключены (не «дёргается» пока идёт запрос).
- **disabled** — `opacity: .5`, `cursor: not-allowed`, hover/active-scale отключены, без
  заливки-акцента (не вводит в заблуждение, что кнопка активна).

### 7.2. Поле ввода (text/email/password/textarea/select)

Структура сверху вниз: `<label>` (`text-sm`, `font-weight-medium`, `color: text-secondary`,
связан через `for`/`id`) → поле → helper/error text (`text-xs`) под полем.

Поле: высота 44px (single-line — совпадает с минимальной зоной нажатия 44×44 из `02-ux.md` §7),
паддинг `space-3 space-4`, `radius-md`, фон `surface`, граница `1px solid border-strong`.

Состояния:
- **default** — граница `border-strong`.
- **hover** — граница `text-secondary` (чуть темнее/светлее в зависимости от темы, без смены
  фона).
- **focus** — граница `accent`, плюс `outline` через `.focus-ring` утилиту (двойной сигнал —
  граница и outline — для людей с цветовой слепотой на сам факт «поле активно»).
- **error** — граница `error`, под полем текст `color: error` с иконкой восклицательного знака,
  `aria-describedby` указывает на текст ошибки (обязательно по `02-ux.md` §7).
- **disabled** — фон `surface-hover`, текст `text-disabled`, граница `border`.
- Пароль — иконка «показать/скрыть» справа внутри поля, зона нажатия 44×44 даже при визуально
  меньшей иконке (паддинг вокруг).
- Поле с автодополнением города — та же оболочка + выпадающий список подсказок ниже
  (`surface-elevated`, `shadow-md`, `radius-md`, максимум 5 строк, разделены `border`).

### 7.3. Карточка (базовая единица)

Фон `surface`, `radius-lg`, `padding: space-5`, тень `shadow-sm` в покое, `shadow-md` на hover
(если карточка кликабельна целиком — вся карточка обёрнута в `<Link>`/`<button>` с
`.interactive-scale`, курсор pointer). Граница не рисуется по умолчанию (тень + разница
`surface`/`bg` уже даёт разделение); граница `1px solid border` добавляется только в темах, где
тень плохо видна на фоне (тёмная тема — легкая граница подстраховывает силуэт карточки, т.к.
чёрные тени на чёрном фоне почти не читаются).

#### Карточка компании в списке результатов поиска
Композиция (мобильный — вертикальная, десктоп-сетка — карточка в колонке):
1. Фото/обложка сверху, `aspect-ratio: 16/9`, `radius-lg` только у верхних углов, `object-fit:
   cover`; поверх — иконка «сердце» (избранное) в кружке `surface-elevated` с полупрозрачностью
   для читаемости на любом фото.
2. Название компании — `text-lg`, `font-weight-semibold`, `text-primary`, одна строка с
   `text-overflow: ellipsis`.
3. Строка рейтинга: звёзды (см. 7.9) + число `4.8 · 132 отзыва` — `text-sm`, `text-secondary`.
4. Если компания не верифицирована — плашка «Профиль не подтверждён» сразу под названием (см.
   7.7), карточка визуально не тускнеет целиком (не как `disabled`), просто теряет строку цены.
5. «Цена от {N} ₽» — `text-base`, `font-weight-semibold`, `color: accent` (единственное место в
   обычной карточке списка, где акцентный цвет используется на тексте — подчёркивает главный для
   решения параметр).
6. Кнопка «Подробнее» — `secondary`, `size sm`, прижата к правому/нижнему краю карточки.

Паддинг между блоками 2–6: `space-2`. Внешний паддинг карточки вокруг фото: фото — edge-to-edge
(без паддинга), текстовый блок — `padding: space-4`.

#### Блок «ТОП-3»
Визуально выделен относительно обычного списка тремя способами одновременно (не одним, чтобы
не полагаться только на цвет — доступность):
1. **Крупный числовой бейдж** «1» / «2» / «3» в левом верхнем углу карточки — кружок `radius-full`
   32px, заливка `accent-subtle`, текст `accent`, `font-weight-bold`; для «1» — заливка `accent`
   сплошная с белым текстом (первое место выделено сильнее двух остальных).
2. **Увеличенный размер и тень**: карточки ТОП-3 используют `shadow-md` в покое (а не `shadow-sm`
   как обычный список) и на ~15% больше внутренних отступов (`space-5` вместо `space-4` у
   текстового блока), плюс более крупный заголовок (`text-lg` → фактически тот же токен, но у
   обычного списка на мобильном допустимо `text-base` для более плотной сетки).
3. **Отдельная секция страницы** с заголовком «ТОП-3 компании города» и, на десктопе, лёгкой
   подложкой `background: var(--gradient-hero)` вокруг всего блока с большим `padding: space-6`
   и `radius-xl` (декоративная, не под текстом — текст остаётся на `surface`-карточках поверх
   подложки) — используется только в теме `gradient`, где это уместно; в темах `dark`/`classic`
   вместо градиентной подложки — просто `background: var(--color-surface-hover)` той же формы
   (консистентный приём «выделенная секция», без противоречия правилу «строгая нейтральная
   палитра»).

#### Вкладки карточки компании
Горизонтальный ряд из 3 пунктов («Услуги и цены» / «Отзывы» / «О нас», для неверифицированной —
только «О нас»), `radius-full` пилюли или подчёркивание — выбран вариант **подчёркивание**
(ближе к «строгому инструменту», меньше decorative-элементов, чем pill-табы):
- Неактивная вкладка: `text-secondary`, `text-base`, `font-weight-medium`, без фона.
- Активная вкладка: `text-primary`, `font-weight-semibold`, снизу полоса 2px `background:
  accent`, `radius-full` у самой полосы.
- Hover неактивной: `color: text-primary` (без смены фона — фон в подложке табов не нужен, чтобы
  не спорить с полосой активной вкладки).
- Focus-visible — стандартный `.focus-ring`.
- Переключение — content fade (`opacity 0→1`, `150ms`), не slide (вкладки не по порядку слева
  направо семантически, slide создал бы ложное ощущение шагов мастера).

### 7.4. Бейджи статусов заказа

Форма: пилюля `radius-full`, паддинг `space-1 space-3`, `text-xs`, `font-weight-semibold`,
маленькая точка-индикатор (6px кружок) слева от текста для дублирования цвета формой/текстом
(не полагаемся только на цвет — как и во всей системе).

| Статус (текст из `02-ux.md`) | Токен цвета | Логика |
|---|---|---|
| «Создан» | `info` (текст) на `info-bg` (фон) | нейтрально-информационный — заказ только что появился, ничего критичного |
| «В работе» | `warning` на `warning-bg` | требует внимания/в процессе |
| «Выполнен» | `success` на `success-bg` | положительный финал |
| «Отменён» | `neutral` на `neutral-bg` | намеренно *не* `error` — отмена заказа не системная ошибка, а нормальный исход процесса; красный зарезервирован за реальными сбоями (ошибки форм, сеть) |

Все 4 сочетания текст/подложка проверены на ≥ 4.5:1 в каждой из трёх тем (см. таблицы палитр в
разделе 3 — тона `success`/`warning`/`error`/`info`/`neutral` посчитаны именно как пара
текст-на-своей-подложке). Бейдж «Новый» (новый заказ в панели компании) использует тот же
`info`-токен, что и «Создан», т.к. семантически это один и тот же статус, увиденный с другой
стороны.

### 7.5. Карточка акции/скидки

Компактная плашка внутри карточки компании (карусель/список, `02-ux.md` §4): фон `accent-subtle`,
граница `1px solid accent` с прозрачностью, `radius-md`, паддинг `space-2 space-3`, содержимое
одной строкой на мобильном: `−{N}%` (`text-base`, `font-weight-bold`, `color: accent`) + название
акции (`text-sm`, `text-primary`) + `до {дата}` (`text-xs`, `text-secondary`). В отдельном разделе
`/company/promotions` та же карточка крупнее (полноценная карточка `surface` + `shadow-sm`), с
бейджем «Истекла» (`neutral` на `neutral-bg`, приглушённая — `opacity: .6` на всю карточку) для
просроченных акций.

### 7.6. Звёздный рейтинг

5 звёзд, размер иконки 16px (в списках/бейджах рейтинга) или 24px (в форме отзыва — крупнее для
удобства нажатия, зона тап-таргета вокруг звезды дополняется до 44×44 через прозрачный паддинг).
Заполненная звезда — `color: star-filled`, пустая — `color: star-empty`, дробный рейтинг (4.8)
рендерится через `clip-path`/градиентную заливку внутри SVG-звезды (не половина видимой звезды
через два разных элемента — линейный градиент внутри `<linearGradient>` SVG с `offset` = дробная
часть). Рядом всегда числовое значение (`4.8 · 132 отзыва`) — never звёзды без цифр, чтобы не
терять точность и для `aria-label="Рейтинг 4.8 из 5, 132 отзыва"` (обязательное требование
`02-ux.md` §7). В интерактивном режиме (форма отзыва, выбор оценки 1–5) — hover на звезде
подсвечивает все звёзды до неё `color: star-filled` + `.interactive-scale` (`scale: 1.05` на
hover каждой звезды), клик фиксирует оценку.

### 7.7. Плашка «неверифицированная компания»

Два места использования с разным весом:
- **В списке/карточке (компактно):** маленький бейдж `text-xs`, `neutral` на `neutral-bg`,
  `radius-full`, иконка серого «часы»/«щит с точкой» слева, текст «Профиль не подтверждён».
  Не красная и не жёлтая намеренно — это не ошибка и не предупреждение об опасности, а
  информационный статус (в противовес зелёному бейджу «Верифицировано» — `success` на
  `success-bg` с иконкой галочки).
- **На публичной карточке компании (расширенно):** горизонтальная плашка на всю ширину
  под шапкой профиля, фон `neutral-bg`, `radius-md`, паддинг `space-3 space-4`, иконка + текст
  «Профиль в процессе проверки, часть информации пока скрыта» (`text-sm`, `text-secondary`).
  Именно она, а не бейдж, отвечает за то, что рядом скрыты вкладки «Услуги» и «Акции» (структурное
  сообщение, а не просто ярлык).
- **В кабинете самой компании (`/company`, заглушка модерации):** та же логика цвета, но в
  крупном формате — центрированная иконка 48px в кружке `neutral-bg`, заголовок «Профиль на
  модерации» (`text-xl`), поясняющий текст, кнопка `secondary` «Редактировать основные данные».

### 7.8. Аватар с кнопкой смены/обрезки

Круг (`radius-full`), три размера: 32px (списки чатов/меню шапки), 48px (карточка отзыва,
строка заказа), 96–128px (настройки/профиль компании — крупный, редактируемый). Если фото не
загружено — плейсхолдер: заливка `accent-subtle`, инициалы username `text-primary`,
`font-weight-semibold`, размер шрифта = 40% диаметра круга.

Редактируемый аватар (настройки клиента/компании): поверх нижней трети круга — полупрозрачный
слой `rgba(0,0,0,.45)` с иконкой камеры, видимый **всегда** на touch (не только по hover, иначе
на мобильном функция не обнаруживается), на десктопе — появляется по hover с `opacity 0→1`,
`150ms`. Клик открывает модал Cropper.js: квадратная/круглая маска обрезки, ползунок зума,
кнопки «Сохранить» (primary) / «Отмена» (secondary) внизу модала. Во время загрузки на сам аватар
поверх кладётся спиннер + затемнение, зона клика блокируется.

### 7.9. Переключатель темы

Видимый компонент в шапке (доступен на каждом экране — `02-ux.md` §5), реализован как
**иконка-триггер + выпадающее меню с сегмент-контролом внутри**, а не голые три кружка на самой
шапке (кружки на шапке заняли бы драгоценное место рядом с колокольчиком/аватаром и на мобильном
375px не поместились бы) — но внутри выпадающего меню три варианта представлены **именно как
кружки-свотчи с подписью**, чтобы решение было визуальным, а не только текстовым списком:

- Триггер: иконка (солнце/полумесяц в зависимости от активной темы), кружок 40×40, hover — фон
  `surface-hover`, `radius-full`. `aria-label="Переключить тему оформления"`.
- Открытое меню: `surface-elevated`, `shadow-lg`, `radius-lg`, паддинг `space-3`, 3 строки-опции
  в столбик (мобильный) или в ряд (десктоп-поповер по правому краю).
- Каждая опция: кружок-свотч 24px слева (сплошная заливка `bg` темы для «Тёмная»/«Классика»,
  `gradient-hero` конкретно этой темы для «Светлая (градиент)» — то есть кружок буквально
  превью фона темы) + подпись («Тёмная»/«Светлая»/«Классика», `text-sm`) + галочка `accent`
  справа у текущей выбранной темы (по `02-ux.md` §5: «текущая тема отмечена галочкой»).
- Активная строка — фон `accent-subtle`, `radius-md`.
- Клик — мгновенная смена `data-theme` на `<html>` + запись в `localStorage`, меню закрывается
  с той же fade-анимацией `150ms`, `Esc` закрывает меню (обязательное требование `02-ux.md` §7).

### 7.10. Модальное окно

`surface-elevated`, `radius-xl`, `padding: space-6`, ширина: 100%−`space-4` с боков на мобильном
(bottom-sheet допустимо для форм на мобильном — выезжает снизу), 480–560px по центру на десктопе.
Подложка — `color-overlay` на весь экран, клик по подложке закрывает модал (кроме форм с
несохранёнными данными — там подтверждение закрытия). Появление — `opacity 0→1` +
`scale 0.96→1`, `200ms`, исчезновение — обратная анимация `150ms`. Заголовок `text-lg
font-weight-semibold`, крестик-закрытие 24px в правом верхнем углу (зона нажатия 44×44), кнопки
действий — в ряд внизу (десктоп: справа налево «Отмена» → «Подтвердить», деструктивные модалки —
фокус по умолчанию на «Отмена»/безопасном варианте, см. `02-ux.md` §6).

### 7.11. Уведомление (тост)

Позиция: правый верхний угол на десктопе, сверху по центру на мобильном (`02-ux.md` §6).
`surface-elevated`, `shadow-lg`, `radius-md`, паддинг `space-3 space-4`, максимальная ширина
360px. Левая цветная полоса 3px + иконка задают тип: успех (`success`), ошибка (`error`),
информация (`info`). Текст `text-sm`, крестик-закрытие справа (зона 44×44 даже при визуально
меньшей иконке). Автозакрытие через 4 секунды с `opacity`-исчезновением `150ms`; `role="status"`
для успеха, `role="alert"` для ошибок (немедленный анонс скринридером — `02-ux.md` §7). Вход —
`translateY(-8px)→0` + `opacity 0→1` на десктопе (сверху), `translateY(8px)→0` на мобильном
(снизу-вверх при появлении сверху экрана выглядит естественнее как «выпадение»), `200ms`.

### 7.12. Таблица (заказы, услуги, статистика — десктоп ≥1024px)

`surface` контейнер, `radius-lg`, `shadow-sm`. Шапка таблицы — `text-xs
font-weight-semibold text-secondary`, `text-transform: uppercase`, `letter-spacing: .04em`, фон
`surface-hover`, нижняя граница `1px solid border-strong`. Строки — паддинг `space-3 space-4`,
разделены `1px solid border`, hover строки — фон `surface-hover` (без scale/тени — таблица должна
оставаться «спокойной», не прыгать при наведении на плотный список). Ячейка цены —
`tabular-nums`, выравнивание по правому краю. Ячейка статуса — бейдж из 7.4. Колонка «Действия» —
кнопки `secondary`/`ghost` `size sm` справа. На мобильном (<768px) та же таблица разворачивается
в карточки (см. 7.3), а не горизонтальный скролл — горизонтальный скролл таблиц на телефоне
плохо обнаруживается пользователем и не соответствует мобильным блокам, описанным в `02-ux.md`
(«Блоки (мобильный)» везде явно описывают карточки, не таблицы).

### 7.13. Пустое состояние

Центрированный блок (вертикально и горизонтально внутри контентной области): иконка/иллюстрация
64px в кружке `surface-hover` (`radius-full`), заголовок/текст пустого состояния из `02-ux.md`
(`text-base`, `text-secondary`, `max-width: 320px`, по центру), кнопка-действие `secondary` или
`primary` под текстом (`space-4` сверху) там, где есть очевидное следующее действие («Найти
компанию», «Выбрать другой город», «Добавить первую услугу»). Не используется тяжёлая
декоративная графика/иллюстрация с множеством цветов — только одноцветная line-иконка в токене
`text-secondary`, чтобы не спорить с однотонной строгой палитрой.

### 7.14. Скелетон загрузки

Класс `.skeleton` из `design-tokens.css`: shimmer-градиент между `surface-hover` и `border`,
анимация `1.4s ease-in-out infinite` (это единственная анимация в системе длиннее 250 мс —
осознанное исключение, т.к. это не hover/active-микровзаимодействие, а индикатор процесса;
`prefers-reduced-motion` всё равно сокращает её длительность до почти статичной, чтобы не
раздражать пользователей, чувствительных к движению).

Формы скелетонов повторяют финальную геометрию контента (не универсальные серые прямоугольники
без учёта макета — обложка скелетон = `aspect-ratio 16/9` как настоящая обложка, круглый
скелетон аватара = `radius-full`, строка таблицы = ряд прямоугольников по ширине колонок).
Каждый скелетон-блок — `aria-busy="true"` `role="status"` с визуально скрытым текстом «Загрузка
содержимого» (обязательное требование `02-ux.md` §7).

## 8. Сводка для оркестратора

- **Визуальное направление:** нейтрально-функциональный маркетплейс-агрегатор с элементами
  финансовой строгости — плотная информационная сетка, один акцентный цвет на тему, семантическая
  статусная палитра, минимум декора.
- **Акцентный цвет:** свой на тему — `#6c63ff` (тёмная), `#7c3aed` (светлая-градиент, тон в
  семье заданного градиента `#a18cd1 → #fbc2eb`, но достаточно насыщенный для функциональных
  элементов), `#1e3a8a` (классика) — плюс единая логика заливок/hover/active (`accent-600/700/800`)
  во всех трёх.
- **Путь к токенам:** `docs/tokens/design-tokens.css` (CSS custom properties + сброс +
  типографика + утилиты фокуса/анимаций, три темы через `data-theme`), `docs/tokens/colors.json`
  (машиночитаемый источник), `docs/tokens/tailwind.tokens.js` (готовый `theme.extend` для
  Tailwind). Полное описание — этот файл, `docs/03-design-system.md`.
