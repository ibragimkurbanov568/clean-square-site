# Дизайн-система NoesDize

Документ описывает визуальное оформление продукта на **двух независимых
уровнях** и то, как фронтендер должен их подключать, не смешивая.

- Уровень 1 — «шкура редактора»: интерфейс самого приложения NoesDize.
  Токены `--nd-*`, файл [`src/styles/tokens.css`](../src/styles/tokens.css).
- Уровень 2 — «темы сайтов»: шесть тем оформления для собираемых
  пользователем сайтов (F4). Токены `--site-*`, файл
  [`src/styles/site-themes.css`](../src/styles/site-themes.css).

---

## 0. Схема изоляции двух пространств имён

**Правило одно и без исключений: `--nd-*` красит приложение, `--site-*`
красит содержимое сайта пользователя. Ни одна переменная не встречается в
обоих файлах.** Это проверено — в `tokens.css` нет ни одного `--site-*`, в
`site-themes.css` нет ни одного `--nd-*` (упоминания в комментариях не
считаются, деклараций нет).

Почему это критично именно для этого продукта: пользователь выбирает тему
для СВОЕГО сайта (например тёмный «Импульс»), при этом интерфейс NoesDize
вокруг кадра предпросмотра должен остаться таким, каким его выбрал сам
разработчик приложения (светлым или тёмным по системной настройке/тумблеру
редактора) — иначе выбор темы сайта случайно перекрасил бы панели, кнопки
и диалоги самого конструктора.

**Как это устроено технически:**

1. `<html>`/корневой узел приложения несёт на себе только токены `--nd-*`
   (из `:root`, `:root[data-theme="dark"]` или медиа-запроса). Весь chrome
   редактора — панель секций, вкладки, диалоги, тосты, кнопка «Скачать
   сайт» — стилизован исключительно через `var(--nd-...)`.
2. Кадр предпросмотра — это `.nd-preview-frame` (токены `--nd-*`: рамка,
   тень, «полоса браузера» — они нейтральны и не зависят от темы сайта, см.
   UX-требование «фон вокруг кадра всегда нейтральный»).
3. Внутри кадра — один-единственный дочерний узел с атрибутом
   `data-site-theme="atlant" | "remeslo" | "impulse" | "vozdukh" | "karnaval" | "barhat"`.
   Всё, что рендерится внутри этого узла (секции сайта: Hero, О компании,
   Услуги…), стилизовано исключительно через `var(--site-...)`. CSS custom
   properties наследуются вниз по дереву, но не поднимаются вверх — поэтому
   смена `data-site-theme` не может «протечь» и перекрасить чтойто снаружи
   этого узла.
4. Экспорт (F7) переносит этот же принцип в файл один-в-один: в
   экспортированном `.html` есть один инлайновый `<style>` с блоком тем сайта
   (только использованная тема или все шесть — на усмотрение фронтендера) и
   `<body data-site-theme="...">` — без единого `--nd-*` внутри, потому что
   экспортируется только сайт, не интерфейс редактора.
5. Переключение темы = смена одного атрибута на одном узле, а не
   перемонтирование поддерева — поэтому фокус, курсор и недописанный текст в
   textarea секции не теряются при смене темы посреди набора (см. «Три
   сложных момента», пункт 3 в `02-ux.md`).

**Как фронтендеру проверить, что он не нарушил границу:**
- grep по компонентам интерфейса редактора не должен находить `--site-`;
- grep по компонентам, рендерящим секции сайта (Hero/About/Services/...),
  не должен находить `--nd-`;
- единственное место, где оба пространства имён видны одновременно в DOM —
  это сам `.nd-preview-frame` (снаружи `--nd-*`, внутри вложенного узла с
  `data-site-theme` — `--site-*`).

## 1. Уровень 1 — визуальное направление редактора

**Направление:** нейтральный, функциональный рабочий инструмент — «плотный
и профессиональный», не «программа-игрушка». NoesDize — это конструктор,
т.е. рабочий инструмент, а не сам творческий продукт; в этом суть
разделения уровней: интерфейс инструмента должен быть тихим и не спорить с
любой из шести ярких/сдержанных тем сайта, которая крутится рядом в кадре
предпросмотра. Отсюда — холодная графитовая нейтраль + один акцент, без
декоративных градиентов и вторичных цветов в chrome.

**Акцентный цвет:** индиго-фиолетовый `#5B48EE` (светлая тема) /
`#8F7FFF` (тёмная тема, светлее для сохранения контраста на тёмном фоне).
Один акцент на весь интерфейс — используется для primary-кнопок, активных
вкладок, выделения активной темы/выбранного чипа, фокус-кольца, прогресса
автосохранения. Второго «декоративного» цвета в chrome нет.

**Шрифт интерфейса:** системный стек
`system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`
— без внешних подключений, одинаково рендерится на Windows/macOS/Linux.

**Важная деталь тёмной темы:** на светлом фоне акцентная кнопка использует
белый текст (`accent-ink: #fff`), а на тёмном фоне — наоборот, тёмный текст
на светло-фиолетовой заливке (`accent-ink: #14141c`), потому что в тёмной
теме сам акцент делается светлее (иначе он тонет в тёмном фоне), а на
светлой заливке белый текст уже не проходит контраст. Это единственная
асимметрия между темами, и она обоснована расчётом, а не произволом.

### 1.2 Шкалы

**Отступы — 8 значений:** `--nd-space-1 4px`, `-2 8px`, `-3 12px`,
`-4 16px`, `-5 24px`, `-6 32px`, `-7 48px`, `-8 64px`.

**Шрифт — 6 размеров:** `--nd-text-xs 12px`, `-sm 14px`, `-base 16px`,
`-lg 18px`, `-xl 24px`, `-2xl 32px`.

**Радиусы:** `--nd-radius-sm 6px` (поля, чипы), `-md 10px` (карточки,
кнопки), `-lg 16px` (модальные окна, кадр предпросмотра), `-full 999px`
(круглые индикаторы, аватар-плашка темы).

**Движение:** `--nd-motion-fast 150ms`, `-base 200ms`, `-slow 250ms`,
`cubic-bezier(0.4, 0, 0.2, 1)`. Анимируются только `opacity` и `transform`.
`@media (prefers-reduced-motion: reduce)` сжимает все длительности до
0.001ms — правило в `tokens.css`, глобальное, не требует ручного
дублирования в компонентах.

Темы различаются не оттенком, а характером целиком: палитрой, парой

они соотносятся с отраслями из мастера (F1), это рекомендация, не

`--site-accent-ink`/`--site-text`, для которых контраст уже проверен выше.

### 2.3 Решение по шрифтам и офлайн-экспорту

**Решение: только системные стеки, ни одного шрифта с внешнего CDN — ни в
превью, ни в экспорте.** Это не временное упрощение, а прямое следствие
двух требований ТЗ:

1. F7/критерии готовности: экспортированный `.html` не должен обращаться к
   сети и обязан выглядеть идентично предпросмотру при открытии `file://`.
2. Принятое допущение ТЗ №9 («Пользовательские загружаемые шрифты —
   используются только системные/локально подключённые шрифты»).

Если бы темы подключали шрифт через `<link>` на Google Fonts во время
работы приложения (когда сеть есть), то офлайн-экспорт увидел бы другой
fallback шрифта, чем «живой» онлайн-предпросмотр — предпросмотр и экспорт
разошлись бы визуально. Поэтому каждая тема — это заранее подобранная пара
широко предустановленных системных гарнитур с длинным списком запасных
шрифтов, которая рендерится одинаково что в браузере с сетью, что без неё,
что при открытии сохранённого файла с диска. Различие характера шрифтовых
пар достигается не экзотичностью гарнитуры, а комбинацией: засечки/без
засечек, моноширинный/пропорциональный, трекинг (`--site-heading-tracking`)
и регистр (`--site-heading-transform: uppercase` только у «Импульса»).

### 2.4 Плотность и форма

`--site-space-unit` — единственная переменная плотности на тему; вся сетка
отступов компонентов сайта считается через `calc(var(--site-space-unit) * N)`
с множителями `1 / 2 / 3 / 4 / 6 / 8 / 12 / 16` (та же логика «шкалы из
восьми значений», что и в токенах редактора, только выраженная одной базовой
единицей на тему, а не восемью захардкоженными числами — так плотность темы
можно поменять в одном месте). Радиусы (`-radius-sm/md/lg`) заданы явно на
тему, потому что форма — часть характера: `0–4px` у «Импульса» (острая,
техно), `14–32px` у «Карнавала» (мягкая, игривая).

## 3. Анатомия базовых компонентов (Уровень 1, интерфейс редактора)

Все размеры — в токенах `--nd-*`. Компонент не должен содержать
хардкод-цвет/отступ мимо переменной.

### 3.1 Кнопка

- Высота: 40px (primary/secondary), 32px (compact, внутри строки секции).
- Паддинг по горизонтали: `--nd-space-4`.
- Радиус: `--nd-radius-md`.
- Шрифт: `--nd-text-sm`, `font-weight: --nd-font-weight-medium`.
- **Primary** (например «Создать сайт», «Скачать сайт»): фон
  `--nd-color-accent`, текст `--nd-color-accent-ink`; hover — фон
  `--nd-color-accent-hover`, `transform: translateY(-1px)` за
  `--nd-motion-fast`; active — фон `--nd-color-accent-active`,
  `transform: translateY(0)`; focus-visible — кольцо
  `--nd-focus-ring-color` с отступом `--nd-focus-ring-offset`; disabled —
  фон `--nd-color-surface-sunken`, текст `--nd-color-text-disabled`, курсор
  `not-allowed`, без hover-реакции.
- **Secondary** (например «Отмена»): прозрачный фон, граница
  `1px solid var(--nd-color-border-strong)`, текст `--nd-color-text`; hover
  — фон `--nd-color-surface-sunken`.
- **Danger** (например «Удалить» в диалоге): фон `--nd-color-danger`, текст
  `--nd-color-danger-ink`; hover — затемнение на ~10% (локальная переменная
  внутри компонента, не токен уровня системы).
- **Готово ✓** (пост-экспорт, 1.5с): фон `--nd-color-success`, текст
  `--nd-color-accent-ink`, без анимации перехода цвета (мгновенная смена
  подписи и фона, т.к. это статус-сообщение, а не hover).

### 3.2 Поле ввода (текст, textarea)

- Высота (однострочное): 40px; textarea — `min-height: 96px`, растёт по
  контенту до предела, дальше внутренняя прокрутка.
- Паддинг: `--nd-space-3` по вертикали, `--nd-space-4` по горизонтали.
- Фон: `--nd-color-surface-sunken`. Граница: `1px solid var(--nd-color-border-strong)`.
- Радиус: `--nd-radius-sm`.
- Placeholder — `--nd-color-text-disabled`.
- Focus: граница меняется на `--nd-color-accent`, плюс общее
  `focus-visible`-кольцо из `tokens.css`.
- Ошибка (превышение лимита символов, пустое обязательное поле): граница
  `--nd-color-danger`, счётчик символов под полем красится в
  `--nd-color-danger` и получает `aria-live="polite"`.
- Счётчик символов (`12 / 80`): `--nd-text-xs`, `--nd-color-text-muted`,
  меняется на `--nd-color-danger` при превышении.
- Пометка «изменено вручную»: `--nd-text-xs`, `--nd-color-accent`, рядом с
  подписью поля.

### 3.3 Карточка (проект в списке, тип секции в библиотеке блоков, образец темы)

- Фон: `--nd-color-surface`. Радиус: `--nd-radius-md`. Тень: `--nd-shadow-sm`
  в покое, `--nd-shadow-md` на hover (только у кликабельных карточек, переход
  `--nd-motion-base`).
- Граница: `1px solid var(--nd-color-border)` (декоративная, не
  обязана быть ≥3:1, т.к. дублируется тенью).
- Паддинг: `--nd-space-4`–`--nd-space-5` в зависимости от плотности
  контента.
- Активное/выбранное состояние (карточка темы, чип отрасли/тона): граница
  `2px solid var(--nd-color-accent)`, фон `--nd-color-accent-subtle`,
  подпись «Текущая»/чек-иконка в `--nd-color-accent`.
- Карточка проекта: цветная плашка сверху высотой 6px, залитая градиентом
  из `--site-accent`/`--site-accent-2` **той темы, которая сохранена в
  проекте** — единственное место, где Уровень 1 сознательно и точечно
  использует значения токенов Уровня 2 как статичный превью-градиент
  (не через `var()`, а как захардкоженный в момент рендера inline-стиль на
  основе данных темы проекта, а не через применение `data-site-theme` к
  chrome-элементу — переменные `--nd-*` карточки при этом не переопределяются).

### 3.4 Модальное окно (диалог подтверждения, библиотека блоков)

- Скрим: `--nd-color-overlay-scrim` на весь экран.
- Контейнер: `--nd-color-surface-raised`, `--nd-radius-lg`, `--nd-shadow-lg`,
  максимальная ширина 480px (диалоги подтверждения) / 640px (библиотека
  блоков), паддинг `--nd-space-6`.
- Заголовок: `.nd-heading-lg`. Текст: `--nd-text-base`,
  `--nd-color-text-muted`.
- Кнопки — в ряд, справа, отступ `--nd-space-3` между ними; для опасных
  действий (удалить проект/секцию, перегенерировать) danger-кнопка справа,
  фокус по умолчанию — на secondary «Отмена» (безопасный дефолт).
- Появление: `opacity 0→1` + `transform: scale(0.96→1)` за
  `--nd-motion-base`; при `prefers-reduced-motion` — мгновенно.
- Focus trap, закрытие по `Esc`, возврат фокуса на элемент, открывший
  модалку (см. `02-ux.md`, раздел «Доступность»).
- На мобильном библиотека блоков превращается в bottom sheet: тот же
  контейнер, но `border-radius` только сверху (`--nd-radius-lg 0 0`… то
  есть верхние два угла), выезжает снизу (`translateY(100%→0)`).

### 3.5 Уведомление (тост, баннер)

- **Тост** (например «Готово! Файл … скачан»): плавающий блок внизу по
  центру (мобильный) / внизу справа (десктоп), фон
  `--nd-color-surface-raised`, тень `--nd-shadow-md`, радиус `--nd-radius-md`,
  паддинг `--nd-space-3` `--nd-space-4`, автоматически исчезает через 4с,
  появление — `opacity`+`translateY` за `--nd-motion-base`,
  `aria-live="polite"`.
- **Баннер** (например «Не удалось сохранить локально»): на всю ширину
  сверху рабочей области, фон `--nd-color-danger-bg`, текст
  `--nd-color-text`, левая полоса `4px solid var(--nd-color-danger)`,
  паддинг `--nd-space-3` `--nd-space-4`, не исчезает автоматически, пока не
  устранена причина (в отличие от тоста).
- **Индикатор автосохранения** (в шапке): текст `--nd-text-sm`
  `--nd-color-text-muted` в состоянии «Сохранение…», меняется на
  `--nd-color-success` с иконкой-галочкой в состоянии «Сохранено» на 2с,
  затем гаснет (`opacity → 0` за `--nd-motion-slow`).

### 3.6 Таблица/список (список секций, список проектов)

- Строка: высота ≥56px (десктоп) / зона нажатия иконок ≥44×44px
  (мобильный, требование доступности из `02-ux.md`).
- Разделитель между строками: `1px solid var(--nd-color-border)`.
- Hover строки: фон `--nd-color-surface-sunken`, переход `--nd-motion-fast`.
- Новая добавленная строка: подсветка фоном `--nd-color-accent-subtle` на
  1.5с, затем плавный переход обратно к `--nd-color-surface` за
  `--nd-motion-slow` (при выключенных эффектах/reduced-motion — подсветка
  всё равно допустима, т.к. это статус-индикация, а не декоративная
  анимация появления; сам переход между цветами становится мгновенным).
- Sticky-заголовок (при 10+ строках): `position: sticky; top: 0`, фон
  `--nd-color-surface`, `box-shadow: var(--nd-shadow-sm)` только когда
  список проскроллен (появляется по классу при `scrollTop > 0`).
- Заблокированная иконка (например корзина у последней секции): `opacity
  0.4`, курсор `not-allowed`, `aria-disabled="true"`, tooltip по
  hover/долгому нажатию.

### 3.7 Пустое состояние (стартовый экран без проектов, редактор с одной Hero-секцией)

- Центрированный блок, максимальная ширина ~420px, паддинг
  `--nd-space-8` сверху/снизу.
- Декоративная иллюстрация-заглушка: круг/плашка `--nd-radius-full` или
  `--nd-radius-lg`, залитая мягким градиентом на основе `--nd-color-accent`
  (единственное место в chrome, где допустим градиент, — потому что это не
  функциональный элемент интерфейса, а декоративная иллюстрация).
- Заголовок: `.nd-heading-lg`. Пояснение: `--nd-text-base`,
  `--nd-color-text-muted`, максимальная ширина строки ~52 символа для
  читаемости.
- Основная кнопка (primary) сразу под текстом, `--nd-space-5` сверху.
