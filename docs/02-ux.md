# UX-спецификация

Продукт: **NoesDize** — локальный конструктор одностраничных сайтов. Работает офлайн,
без регистрации, без сервера. Данные — в `localStorage` вкладки браузера.

Документ описывает 3 маршрутных экрана и 4 оверлея (диалоги/шторки), их состояния,
дословные тексты интерфейса и раскладку для 375 / 768 / 1440px.

---

## Карта экранов

```
/                         Стартовый список проектов
 ├─ [оверлей] Диалог «Удалить проект»
 │
 └─ /new                  Мастер создания
     │  (кнопка «Создать первый сайт» / «Создать новый сайт»)
     │
     └─ /editor/:id       Редактор + предпросмотр
         │  (после нажатия «Создать сайт» в мастере,
         │   либо напрямую с / по кнопке «Открыть» на карточке проекта)
         │
         ├─ [оверлей] Библиотека блоков (добавление секции)
         ├─ [оверлей] Диалог «Удалить секцию»
         └─ [оверлей] Диалог «Перегенерировать все тексты»
```

**Кто куда попадает:**
- Новый пользователь без сохранённых проектов стартует на `/`, видит пустое
  состояние и идёт в `/new`.
- Пользователь с сохранёнными проектами стартует на `/`, видит список карточек и
  либо открывает существующий проект (`/editor/:id`), либо создаёт новый (`/new`).
- `/editor/:id` — единственный маршрут, где происходит вся работа: правка,
  предпросмотр, тема, эффекты, экспорт. Все оверлеи открываются и закрываются
  поверх него, не меняя URL.
- С любого экрана есть путь назад (стрелка «Назад» в шапке) и путь к главному
  действию (кнопка «Скачать сайт» видна в редакторе постоянно, а из списка и
  мастера до неё не больше одного дополнительного перехода).

**Правило «три клика до цели».** Главное действие приложения — получить готовый
экспортированный сайт. Путь от старта:
1. `/` → нажать **«Создать первый сайт»** (или «Создать новый сайт»).
2. `/new` → заполнить поле имени, при желании тронуть чипы отрасли/тона (уже
   есть значения по умолчанию — «Прочее» и «Дружелюбный»), нажать **«Создать
   сайт»**.
3. `/editor/:id` → нажать **«Скачать сайт»**.

Три касания между экранами. Внутри шага 2 можно ничего не выбирать, кроме
названия, — мастер соберёт сайт со значениями по умолчанию, поэтому правило
выполняется даже без единой правки текста или темы.

## Основные потоки

### F1 — Мастер создания проекта
1. На `/` пользователь нажимает «Создать первый сайт» (пустой список) или
   «Создать новый сайт» (обычный список).
2. Открывается `/new`.
3. Пользователь вводит название в поле «Название бизнеса».
4. Выбирает одну карточку отрасли из 7.
5. Выбирает один вариант тона из 4.
6. Нажимает «Создать сайт».
7. Приложение генерирует `id`, собирает 4 секции — Hero, О компании, Услуги,
   Контакты — с текстами по словарю выбранной пары «отрасль + тон», применяет
   тему по умолчанию «Aurora (светлая)», включает эффекты, сохраняет проект в
   `localStorage`, переходит на `/editor/:id`.
8. Если имя совпадает с уже существующим проектом, автоматически добавляется
   суффикс «(2)», «(3)» и т.д.; в редакторе один раз показывается тост:
   «Название уже занято — сайт сохранён как «Кофейня Атмосфера (2)»».
   - **Ошибка (пустое имя):** поле «Название бизнеса» получает красную рамку,
     кнопка вместо подписи «Создать сайт» показывает недоступную подпись
     «Введите название» и не реагирует на нажатие.
   - **Ошибка (не выбраны отрасль/тон):** при нажатии «Создать сайт» с
     заполненным именем, но без выбранной отрасли или тона, соответствующий
     блок чипов подсвечивается красной рамкой, под ним появляется текст
     «Выберите значение», перехода на редактор не происходит.

### F2 — Библиотека блоков и управление секциями
1. В редакторе на вкладке «Секции» виден список текущих секций проекта.
2. Пользователь нажимает «Добавить секцию» → открывается оверлей «Библиотека
   блоков» со списком из 10 типов (иконка, название, короткое описание).
3. Выбирает тип → секция добавляется в конец списка со сгенерированным текстом
   под текущую пару «отрасль + тон», оверлей закрывается, новая строка на 1.5
   секунды получает подсветку и список докручивается к ней; предпросмотр сразу
   показывает новую секцию.
4. Порядок секций меняется перетаскиванием строки за иконку `⋮⋮` или нажатием
   стрелок «▲»/«▼» на строке — предпросмотр обновляется мгновенно.
5. Удаление — иконка корзины на строке → диалог подтверждения → «Удалить»
   убирает секцию, пересчитывает `order` у остальных, предпросмотр обновляется.
6. Правка текста — иконка карандаша на строке → строка разворачивается в форму
   редактирования (десктоп/планшет) или открывает под-экран правки (мобильный)
   с полями «Заголовок», «Текст», при необходимости «Элементы» и «Текст кнопки».
   - **Ошибка (лимит 12 секций):** кнопка «Добавить секцию» скрывается, на её
     месте появляется текст «Достигнут предел секций».
   - **Ошибка (последняя секция):** иконка корзины у единственной оставшейся
     секции неактивна, подсказка при наведении/долгом нажатии: «Нельзя удалить
     единственную секцию».

### F3 — Локальная генерация текста по отрасли и тону
1. На вкладке «Настройки» пользователь меняет «Отрасль» или «Тон».
2. Приложение мгновенно, без перезагрузки и без сети, пересобирает заголовки,
   абзацы и списки во всех полях, где `isCustomText = false`, по словарю новой
   комбинации. Предпросмотр обновляется в реальном времени, без спиннера — эта
   операция синхронна и незаметна по времени.
3. Поля, которые пользователь уже правил вручную (`isCustomText = true`),
   при этой автоматической пересборке не трогаются — визуально ничего не
   меняется в тех строках, где текст свой.
4. Чтобы принудительно перезаписать вообще всё, включая ручные правки,
   пользователь нажимает отдельную кнопку «Перегенерировать все тексты» →
   открывается оверлей-подтверждение (см. ниже) → после согласия предпросмотр
   на короткое время (несколько сотен миллисекунд) показывает спиннер с
   подписью «Пересобираем тексты…», затем все поля обновляются разом.
   - **Ошибка:** нет отдельной ветки ошибки для самой генерации (детерминированный
     локальный расчёт не может завершиться неудачей); при сбое записи в
     `localStorage` показывается общий баннер сохранения (см. F8).

### F4 — Темы оформления
1. На вкладке «Настройки» в блоке «Тема оформления» — сетка из 6+ образцов:
   кружок с миниатюрой палитры, под ним имя темы и пометка «светлая»/«тёмная».
2. Пользователь нажимает на образец → мгновенно, без перезагрузки, во всём
   предпросмотре меняются фон, поверхности, текст, акцентный цвет и пара
   шрифтов; активный образец получает рамку-выделение и подпись «Текущая».
   - **Ошибка:** отдельного состояния ошибки нет — набор тем статический и
     локальный, применение не может провалиться логически; если не удаётся
     сохранить выбор в `localStorage`, наверху появляется общий баннер «Не
     удалось сохранить локально» (тема при этом уже применена в памяти вкладки).

### F5 — Живой предпросмотр с адаптивностью
1. Любое изменение — текст секции, состав и порядок секций, тема, эффекты —
   сразу отражается в кадре предпросмотра (десктоп/планшет: правая панель;
   мобильный: вкладка «Просмотр»), без перезагрузки и без отдельной кнопки
   «Обновить».
2. Над кадром предпросмотра — переключатель из трёх кнопок: «Десктоп»,
   «Планшет», «Моб.». Выбор меняет ширину кадра (≈1200 / 768 / 375px);
   содержимое остаётся читаемым, горизонтальная прокрутка не появляется —
   кадр масштабируется/центрируется в доступном пространстве панели.
3. Активная кнопка viewport подсвечена; выбор сохраняется в `project.viewport`
   (влияет только на интерфейс редактора, не на экспортированный файл).
   - **Ошибка:** отдельной ветки нет; если все секции скрыты (через
     глаз-переключатель на каждой строке), кадр показывает пустое состояние
     экрана «Редактор» (см. ниже).

### F6 — Визуальные эффекты с уважением к reduced motion
1. На вкладке «Настройки» в блоке «Эффекты» — тумблер «Анимации и переходы»
   (по умолчанию включён).
2. Включено: секции появляются с плавным движением/затуханием при прокрутке
   кадра предпросмотра, кнопки и карточки получают плавный hover-переход,
   hero-секция — анимированный градиент или «стеклянная» поверхность.
3. Пользователь выключает тумблер вручную → все анимации и переходы пропадают
   сразу и заметно (само отключение происходит без плавного перехода — контраст
   должен быть очевиден).
4. Если в операционной системе включена настройка «уменьшить движение»
   (`prefers-reduced-motion: reduce`), анимации появления при прокрутке не
   запускаются независимо от положения тумблера; под тумблером появляется
   пояснение: «Ваша система запросила уменьшённые анимации: появление секций
   отключено, эффекты наведения остаются». Сам тумблер остаётся в положении
   «включено», если пользователь его не трогал.
   - **Ошибка:** нет; поведение полностью детерминировано системной настройкой
     и локальным состоянием тумблера.

### F7 — Экспорт в единый HTML-файл
1. Кнопка «Скачать сайт» видна постоянно в шапке редактора (десктоп/планшет)
   и на вкладке «Просмотр» (мобильный).
2. Кнопка активна, только если в проекте есть хотя бы одна видимая секция
   типа Hero; иначе она отображается неактивной (приглушённый цвет, курсор
   «недоступно»), при наведении/долгом нажатии — подсказка «Добавьте видимую
   секцию Hero, чтобы включить экспорт».
3. Пользователь нажимает «Скачать сайт» → приложение синхронно собирает один
   `.html`-файл с инлайновыми `<style>` и `<script>` (без внешних ссылок),
   браузер сохраняет файл с именем `<транслитерация-названия-проекта>.html`.
4. Кнопка на 1.5 секунды показывает состояние «Готово ✓», затем возвращается к
   подписи «Скачать сайт»; одновременно появляется тост: «Готово! Файл
   «кофейня-atmosfera.html» скачан.» Навигации при этом не происходит — редактор
   остаётся на месте.
   - **Ошибка:** если по какой-то причине (например, гонка состояний — Hero
     скрыли ровно в момент клика) экспорт запускается без видимой Hero-секции,
     показывается тост «Добавьте секцию Hero перед экспортом», файл не
     скачивается.

### F8 — Сохранение и список проектов
1. Любое изменение в редакторе (текст, секции, тема, эффекты, отрасль, тон,
   выбор viewport) с задержкой ~500мс после последнего действия автоматически
   сохраняется в `localStorage`; `updatedAt` обновляется, индикатор в шапке
   показывает «Сохранение…», затем «Сохранено».
2. На `/` карточка проекта показывает: название, «Изменено 6 сент, 14:32»,
   цветную плашку темы, кнопки «Открыть» и «Удалить».
3. «Открыть» → переход на `/editor/:id`, полностью восстанавливаются секции,
   тексты, тема, эффекты, отрасль, тон, последний выбранный viewport.
4. «Удалить» → оверлей-подтверждение → «Удалить» стирает запись из
   `localStorage`, карточка исчезает из списка.
   - **Ошибка (сбой записи):** баннер «Не удалось сохранить локально» наверху
     редактора, работа продолжается в памяти вкладки, следующее изменение
     повторяет попытку сохранения автоматически.
   - **Ошибка (сбой чтения списка):** на `/` вместо списка — баннер ошибки и
     кнопка «Создать новый проект»; ранее сохранённые проекты в этом случае не
     отображаются, но приложение не падает.

## Экраны

### Стартовый список проектов (`/`)

**Назначение.** Точка входа: показать сохранённые проекты, дать создать новый
или открыть/удалить существующий.

**Блоки, мобильный (375):**
1. Шапка: логотип-надпись «NoesDize», под ней короткая строка «Соберите
   красивый сайт за пару минут — без интернета и регистрации».
2. Поле поиска «Найти проект по названию» — только если проектов больше 9.
3. Кнопка «Создать новый сайт» — на всю ширину, primary, сразу под шапкой
   (или под полем поиска, если оно есть).
4. Список карточек проектов, каждая на всю ширину, вертикально друг под другом.

**Блоки, десктоп (1440):**
1. Шапка: логотип слева, поле поиска (если нужно) и кнопка «Создать новый сайт»
   справа, всё в одну строку.
2. Сетка карточек проектов, 3 колонки, ниже шапки.

**Карточка проекта:** цветная плашка сверху (градиент/акцент темы проекта),
название проекта, строка «Изменено 6 сент 2026, 14:32», две кнопки: «Открыть»
(primary) и «Удалить» (иконка корзины, вторичная).

**Интерактивные элементы:** кнопка «Создать новый сайт»/«Создать первый сайт»,
поле поиска (фильтрует список по подстроке в названии без учёта регистра),
кнопка «Открыть» на карточке, кнопка «Удалить» на карточке (открывает диалог
подтверждения).

**Состояния:**
- *Пустое.* Нет сохранённых проектов. Вместо списка — крупный блок по центру:
  иллюстрация-плейсхолдер (декоративный градиент), заголовок «Соберите свой
  первый сайт», текст «NoesDize собирает одностраничный сайт с текстами,
  темой оформления и эффектами — прямо в браузере, без регистрации и
  интернета», кнопка «Создать первый сайт».
- *Загрузка.* На время чтения `localStorage` (доли секунды) — 3 карточки-
  скелетона с пульсирующими серыми блоками вместо текста и кнопок; шапка и
  кнопка «Создать новый сайт» уже кликабельны.
- *Ошибка.* `localStorage` повреждён или недоступен. Баннер сверху: «Не
  удалось прочитать сохранённые проекты. Список недоступен, но вы можете
  начать заново.» Ниже — кнопка «Создать новый проект», карточки не
  показываются.
- *Наполненное (обычное).* От 1 до 9 карточек проектов, кнопка «Создать новый
  сайт» видна постоянно.
- *Много данных.* Больше 9 проектов — появляется поле поиска «Найти проект по
  названию», список/сетка получает вертикальную прокрутку.

### Мастер создания (`/new`)

**Назначение.** Собрать три вводных (название, отрасль, тон) и мгновенно
получить готовый проект из 4 секций.

**Блоки, мобильный (375), сверху вниз:**
1. Шапка: стрелка «Назад» (aria-label «Назад к списку проектов»), заголовок
   «Новый сайт».
2. Поле «Название бизнеса», плейсхолдер «Например, «Кофейня Атмосфера»»,
   счётчик символов «0 / 60» под полем справа.
3. Блок «Отрасль» — заголовок-подпись, ниже 7 чипов в 2 колонки: «Кафе и
   рестораны», «IT и стартапы», «Салон красоты», «Магазин и интернет-магазин»,
   «Услуги и консалтинг», «Образование», «Другое».
4. Блок «Тон текста» — заголовок-подпись, ниже 4 чипа в 1 колонку: «Официальный»,
   «Дружелюбный», «Дерзкий», «Минималистичный».
5. Кнопка «Создать сайт», прижата к низу экрана (sticky footer), всегда видна
   без прокрутки.

**Блоки, десктоп (1440):** те же блоки в одной центрированной колонке шириной
~640px; чипы отрасли — 4 колонки, чипы тона — 4 в один ряд; кнопка «Создать
сайт» — под последним блоком, не прилипающая (места достаточно).

**Интерактивные элементы:** текстовое поле имени, 7 чипов отрасли (выбор
одного, radio-поведение), 4 чипа тона (выбор одного), кнопка «Создать сайт»
(меняет подпись и доступность в зависимости от состояния поля имени).

**Состояния:**
- *Пустое.* Поле имени пустое, ни одна отрасль/тон не выбраны. Кнопка внизу
  показывает вместо «Создать сайт» неактивную подпись «Введите название».
- *Загрузка.* Отдельного состояния нет — сборка происходит мгновенно на
  клиенте; после нажатия «Создать сайт» с валидными данными сразу открывается
  `/editor/:id`.
- *Ошибка.* Имя заполнено, но отрасль и/или тон не выбраны, пользователь
  нажал «Создать сайт» — соответствующий блок чипов подсвечивается красной
  рамкой, под ним текст «Выберите значение», перехода не происходит.
- *Обычное.* Имя заполнено, отрасль и тон выбраны — кнопка активна, подпись
  «Создать сайт».

### Редактор + предпросмотр (`/editor/:id`)

**Назначение.** Основной рабочий экран: управление секциями, текстом, темой,
эффектами и live-предпросмотр в одном месте; отсюда же экспорт.

#### Общая раскладка

**Десктоп (1440).** Два столбца.
- Левая панель, фиксированная ширина 380px: шапка с названием проекта
  (кликабельно для переименования, иконка карандаша), под ней — вкладки
  **«Секции»** / **«Настройки»**. Ниже — содержимое активной вкладки, с
  собственной вертикальной прокруткой при нехватке высоты.
- Правая панель — всё оставшееся пространство: сверху тулбар предпросмотра
  (переключатель «Десктоп / Планшет / Моб.», справа от него — кнопка «Скачать
  сайт»), ниже — центрированный кадр предпросмотра.
- Общая шапка над обеими панелями: стрелка «Назад» (в список проектов),
  индикатор автосохранения справа от названия проекта.

**Планшет (768).** Тот же двухколоночный паттерн, что и на десктопе, но левая
панель сужена до 320px, правая занимает остаток. При нехватке ширины кадр
предпросмотра в режиме «Десктоп» масштабируется (`transform: scale`), чтобы
не создавать горизонтальную прокрутку панели.

**Мобильный (375).** Панели рядом не помещаются — решение: **сегмент-
переключатель «Правка / Просмотр»**, закреплённый сразу под шапкой.
- Шапка (одна строка): стрелка «Назад», название проекта (сокращается
  многоточием при нехватке места), маленький индикатор автосохранения,
  компактная кнопка «Скачать» (иконка + короткая подпись).
- Под шапкой — сегмент-переключатель на всю ширину, две равные половины:
  `[ Правка ]` `[ Просмотр ]`. Активная половина — заливка акцентным цветом
  темы интерфейса (не сайта!), неактивная — прозрачная с обводкой.
- Вкладка **«Правка»**: внутри — те же под-вкладки «Секции» / «Настройки»,
  что и в левой панели десктопа, на всю ширину экрана, с прокруткой.
- Вкладка **«Просмотр»**: тулбар с переключателем «Десктоп / Планшет / Моб.»
  на всю ширину, ниже — кадр предпросмотра на всю оставшуюся высоту. Опция
  «Десктоп» в этом режиме масштабирует кадр внутрь видимой ширины (не даёт
  горизонтальной прокрутки экрана телефона).
- Переключение между «Правка» и «Просмотр» мгновенное, без перезагрузки
  контента: состояние проекта общее, поэтому кадр предпросмотра, открытый на
  «Просмотр», всегда уже отражает последние правки, сделанные на «Правка», —
  даже если вкладка «Просмотр» ни разу не открывалась после правки.

**Важно для фронтендера:** поле ввода текста секции не должно размонтироваться
при переключении сегментов/вкладок внутри «Правка» — значение обновляет
состояние проекта на каждое нажатие клавиши (или сохраняет буфер вне
компонента), иначе непереданные в стейт символы потеряются при уходе с
под-вкладки.

#### Визуальное отделение предпросмотра от интерфейса редактора

Кадр предпросмотра оформлен как «окно браузера в браузере»:
- вокруг кадра — скругление, лёгкая тень и рамка нейтрального (нейтрально-
  серого или тёмно-серого в зависимости от темы **интерфейса приложения**, а
  не темы сайта);
- сверху кадра — тонкая полоса-«шапка браузера»: три декоративных кружка
  (как вкладки/кнопки окна) и центрированная псевдо-адресная строка с
  текстом вида «предпросмотр · кофейня-атмосфера»;
- фон **вокруг** кадра (панель предпросмотра) всегда нейтральный (светло-серый
  в светлой теме интерфейса, тёмно-серый в тёмной), независимо от того, какая
  тема выбрана для самого сайта внутри кадра — так граница «это уже сайт, а
  не приложение» видна всегда, даже если сайт тёмный, а интерфейс светлый, и
  наоборот;
- сам интерфейс редактора (панель «Секции»/«Настройки», кнопки, шапка) всегда
  использует единый системный вид приложения NoesDize и не наследует тему,
  выбранную пользователем для сайта — оформление сайта видно только внутри
  кадра.

#### Панель управления секциями (вкладка «Секции»)

- Заголовок панели: «Секции сайта (N/12)» — N обновляется живо.
- Кнопка «Добавить секцию» рядом с заголовком; при 12 секциях скрывается,
  вместо неё текст «Достигнут предел секций».
- Список строк-секций сверху вниз в порядке `order`. Каждая строка:
  - слева — иконка типа + название на русском («Hero», «О компании»,
    «Услуги», «Преимущества», «Тарифы», «Отзывы», «Галерея», «Призыв к
    действию», «Контакты», «Подвал сайта»);
  - иконка «глаз» — показать/скрыть секцию в предпросмотре и экспорте без
    удаления (aria-label «Скрыть секцию» / «Показать секцию»);
  - стрелки «▲»/«▼» — переместить строку вверх/вниз (у первой строки «▲»
    неактивна, у последней «▼» неактивна);
  - drag-иконка `⋮⋮` — альтернативный способ перестановки перетаскиванием
    (мышью/тачем); стрелки остаются обязательным способом для клавиатуры и
    для точности на мобильном;
  - иконка карандаша «Изменить текст» — раскрывает форму редактирования этой
    секции (заголовок, текст, элементы списка, текст кнопки — набор полей
    зависит от типа секции);
  - иконка корзины «Удалить секцию» — открывает диалог подтверждения;
    неактивна и с подсказкой «Нельзя удалить единственную секцию», если в
    проекте осталась только эта секция.
- При 10+ секциях список получает собственную вертикальную прокрутку, при
  этом заголовок панели и кнопка «Добавить секцию» остаются прикреплёнными
  (sticky) сверху.

**Форма редактирования секции (раскрывается под строкой при клике на
карандаш):**
- Поле «Заголовок» — счётчик «12 / 80» под полем.
- Поле «Текст» (textarea) — счётчик «180 / 600»; для секций без `body` в
  модели поле не показывается.
- Для секций-списков (Услуги, Преимущества, Тарифы, Отзывы, Галерея) — блок
  «Элементы» с карточками-строками (до 8), у каждой — своё текстовое поле
  (для Тарифов — пара «Название» + «Цена», для Отзывов — «Имя» + «Отзыв»),
  кнопка «Добавить элемент» и иконка удаления на каждой строке.
- Для Hero и «Призыв к действию» — поле «Текст кнопки», плейсхолдер «Связаться
  с нами», счётчик «0 / 40».
- Если поле отличается от сгенерированного текста, рядом с его подписью
  появляется маленькая пометка «изменено вручную» — так видно, что это поле
  теперь защищено от автоматической пересборки по F3.
- Кнопка «Свернуть» внизу формы возвращает строку в обычный вид списка.

#### Библиотека блоков (оверлей)

Открывается кнопкой «Добавить секцию». На десктопе/планшете — модальное окно
по центру, на мобильном — шторка снизу (bottom sheet) на весь экран.
- Заголовок «Добавить секцию».
- Список из 10 карточек-типов: иконка, название, короткое описание (например,
  «Тарифы — карточки с ценами и списком возможностей»).
- Клик по карточке сразу добавляет секцию и закрывает оверлей.
- Кнопка «Отмена» / иконка закрытия — закрывает без изменений, возврат в то
  же место панели «Секции», где пользователь был до открытия.

#### Диалог «Удалить секцию» (оверлей)

- Заголовок: «Удалить секцию «Услуги»?»
- Текст: «Это действие нельзя отменить. Тексты и настройки секции будут
  потеряны.»
- Кнопки: «Отмена» (вторичная, фокус по умолчанию), «Удалить» (опасное
  действие, красный акцент).

#### Диалог «Удалить проект» (оверлей, вызывается со стартового экрана)

- Заголовок: «Удалить проект «Кофейня Атмосфера»?»
- Текст: «Это действие нельзя отменить. Все секции и настройки темы будут
  удалены из этого браузера.»
- Кнопки: «Отмена», «Удалить».

#### Вкладка «Настройки»

Разделена на три подблока, сверху вниз:
1. **«Отрасль и тон»** — выбор отрасли (тот же список из 7, что и в мастере),
   выбор тона (4 варианта), кнопка «Перегенерировать все тексты» с подписью
   под ней: «Перезапишет и тексты, изменённые вручную.»
2. **«Тема оформления»** — сетка образцов из 6+ тем, у каждой — кружок с
   миниатюрой палитры, имя и пометка «светлая»/«тёмная»; активная тема
   отмечена рамкой и подписью «Текущая».
3. **«Эффекты»** — тумблер «Анимации и переходы», под ним пояснение:
   «Появление секций при прокрутке, hover-эффекты кнопок и карточек,
   стеклянная поверхность в Hero.» При активном системном
   `prefers-reduced-motion` под тумблером дополнительно: «Ваша система
   запросила уменьшённые анимации: появление секций отключено, эффекты
   наведения остаются.»

#### Диалог «Перегенерировать все тексты» (оверлей)

- Заголовок: «Перегенерировать все тексты?»
- Текст: «Все заголовки, абзацы и списки будут собраны заново по текущей
  отрасли и тону — включая поля, которые вы редактировали вручную. Отменить
  это действие нельзя.»
- Кнопки: «Отмена», «Перегенерировать» (опасное действие).
- После подтверждения: спиннер на кадре предпросмотра с подписью «Пересобираем
  тексты…» на короткое время, затем все поля обновляются.

**Состояния экрана «Редактор»:**
- *Пустое.* Проект содержит ровно одну секцию Hero с текстом-заглушкой (это
  состояние — редкий крайний случай: например, пользователь удалил все
  секции, кроме последней; обычный путь через мастер сразу создаёт 4
  заполненные секции и попадает в состояние «Обычное»). Над кадром
  предпросмотра — плашка-подсказка: на десктопе/планшете «Добавьте секции
  слева, чтобы собрать сайт», на мобильном (вкладка «Просмотр») — «Откройте
  вкладку «Правка» и нажмите «Добавить секцию», чтобы собрать сайт».
- *Загрузка.* Спиннер с подписью «Пересобираем тексты…» поверх кадра
  предпросмотра — только во время «Перегенерировать все тексты»; все прочие
  изменения (текст, порядок, тема, эффекты, viewport) применяются без
  индикатора, так как выполняются мгновенно.
- *Ошибка.* Две независимые ветки: (1) попытка экспорта без видимой Hero-секции
  — тост «Добавьте секцию Hero перед экспортом», кнопка «Скачать сайт» в
  обычном случае для этого просто неактивна заранее; (2) сбой сохранения в
  `localStorage` — постоянный баннер сверху экрана «Не удалось сохранить
  локально», под ним при необходимости уточнение «Работа продолжается в этой
  вкладке, но изменения не сохраняются на диск.»
- *Обычное.* Проект с секциями (обычно 4 сразу после мастера), панель
  «Секции»/«Настройки» слева (или на вкладке «Правка»), кадр предпросмотра
  справа (или на вкладке «Просмотр»), кнопка «Скачать сайт» активна.
- *Много данных.* 10+ секций — список слева/на вкладке «Правка» получает
  вертикальную прокрутку с прикреплённым заголовком и кнопкой «Добавить
  секцию»; кадр предпросмотра прокручивается независимо от списка секций.

## Навигация и структура

- **Маршруты:** `/` (список), `/new` (мастер), `/editor/:id` (редактор). Это
  единственные три URL приложения; все диалоги и шторки — оверлеи без смены
  URL, управляются локальным UI-состоянием.
- **Кнопка «Назад»** есть в шапке `/new` и `/editor/:id`, всегда ведёт на `/`.
  Перед уходом из редактора автосохранение уже произошло (debounce), поэтому
  потери данных при уходе назад не бывает.
- **Кнопка «Назад» браузера** должна вести себя так же, как кнопка в
  интерфейсе (использовать `history`), чтобы не создавать несогласованных
  состояний между системной навигацией и внутренней.
- **Мобильный сегмент-переключатель «Правка / Просмотр»** — не является
  навигацией между экранами (URL не меняется), это переключение вида одного и
  того же экрана `/editor/:id`; ведёт себя как `role="tablist"` с двумя
  `role="tab"`.
- **Хлебных крошек нет** — глубина навигации всего 2 уровня (`/` →
  `/new`/`/editor/:id`), они избыточны.
- **Тупиков нет:** из мастера всегда можно вернуться к списку без создания
  проекта; из редактора всегда можно вернуться к списку (проект уже
  автосохранён — при повторном открытии ничего не потеряется); из любого
  оверлея есть «Отмена»/крестик, возвращающие в исходную точку без побочных
  эффектов.

## Микровзаимодействия

- **Создание проекта.** Нажатие «Создать сайт» → короткий переход
  (fade/slide, ~150мс, отключается при выключенных эффектах или
  `prefers-reduced-motion`) от `/new` к `/editor/:id`.
- **Добавление секции.** Новая строка в списке подсвечивается фоном на 1.5
  секунды и плавно проявляется (при включённых эффектах); список
  автоматически докручивается к новой строке.
- **Удаление секции/проекта.** После подтверждения строка/карточка исчезает с
  анимацией сжатия по высоте (~200мс) при включённых эффектах; при выключенных
  эффектах или `prefers-reduced-motion` — исчезает мгновенно, без анимации.
- **Перетаскивание секции.** Во время перетаскивания на месте будущей позиции
  показывается пунктирный плейсхолдер; отпускание — мгновенный пересчёт
  `order` и обновление предпросмотра; отмена (Esc или отпускание вне списка)
  возвращает строку на исходное место без изменений.
- **Перегенерация всех текстов.** Кнопка «Перегенерировать» в диалоге на время
  операции переходит в состояние «Перегенерируем…» и блокируется от повторного
  нажатия; кадр предпросмотра показывает спиннер; повторный запуск операции,
  пока первая не завершилась, невозможен.
- **Автосохранение.** Индикатор в шапке редактора проходит цикл: «Сохранение…»
  (с иконкой-спиннером) во время debounce-паузы после ввода → «Сохранено» (с
  галочкой) на 2 секунды → индикатор гаснет до следующего изменения. При
  ошибке — постоянный баннер «Не удалось сохранить локально» вместо цикла.
- **Экспорт.** Клик по «Скачать сайт» → браузер сразу инициирует скачивание
  файла (без промежуточной загрузки/спиннера, так как сборка синхронна) →
  кнопка на 1.5 секунды показывает «Готово ✓» → тост с именем скачанного
  файла. Редактор не перезагружается и не теряет состояние.
- **Потеря сети.** Приложение не выполняет сетевых запросов ни на одном этапе
  работы (генерация, сохранение, экспорт — всё локально), поэтому отключение
  сети не меняет поведение и не требует отдельного индикатора «офлайн».
- **Выключение эффектов.** Само переключение тумблера — мгновенное, без
  плавного перехода, чтобы разница «было/стало» была наглядно видна сразу.

## Доступность

- **Порядок фокуса в редакторе:** «Назад» → название проекта → вкладки
  «Секции»/«Настройки» (или сегменты «Правка»/«Просмотр» на мобильном) →
  содержимое активной вкладки сверху вниз → переключатель viewport →
  «Скачать сайт».
- **Все иконки-кнопки** имеют `aria-label` дословно: «Скрыть секцию» / «Показать
  секцию», «Переместить секцию вверх», «Переместить секцию вниз», «Изменить
  текст секции», «Удалить секцию», «Переименовать проект», «Назад к списку
  проектов», «Удалить проект».
- **Модальные оверлеи** (библиотека блоков, оба диалога подтверждения)
  перехватывают фокус (focus trap), закрываются по `Esc` (эквивалент кнопки
  «Отмена»), после закрытия фокус возвращается на элемент, который открыл
  оверлей.
- **Сегмент-переключатель «Правка/Просмотр»** и вкладки «Секции/Настройки»
  реализованы как `role="tablist"`/`role="tab"` с `aria-selected` и управлением
  стрелками влево/вправо с клавиатуры, а не только кликом.
- **Замена drag-and-drop.** Перетаскивание секций дублируется кнопками
  «▲»/«▼», доступными с клавиатуры (Tab + Enter/Space) — нативный HTML5
  drag-and-drop без такой замены недоступен пользователям клавиатуры и части
  скринридеров.
- **Живые области.** Изменение статуса автосохранения и появление тостов
  оборачиваются в `aria-live="polite"`, чтобы сообщения озвучивались
  скринридером без похищения фокуса у текущего поля ввода.
- **Размер зон нажатия.** На мобильной раскладке (375) все интерактивные
  иконки (глаз, стрелки, карандаш, корзина, drag-хендл) — не меньше 44×44px
  зоны нажатия, даже если сама иконка визуально меньше.
- **Контраст и reduced motion.** Все 6+ тем должны обеспечивать контраст
  текста к фону не хуже WCAG AA как в светлом, так и в тёмном варианте;
  `prefers-reduced-motion: reduce` отключает анимации появления автоматически
  независимо от состояния тумблера «Эффекты» (см. F6) — это системное
  поведение, а не настройка на усмотрение фронтендера.

## Три сложных момента отдельно

**1. Первый вход без сохранённых проектов.** Пользователь открывает
приложение впервые. `/` сразу показывает не список (его ещё нет), а
крупный экран-приглашение: иллюстрация, заголовок «Соберите свой первый
сайт», поясняющий текст и одна кнопка «Создать первый сайт». Никакого
предварительного «пустого списка с нулём карточек» с крестиками — сразу
понятный призыв к действию. После создания первого проекта пользователь
попадает в `/editor/:id`; если он вернётся стрелкой «Назад» на `/`, список
уже покажет одну карточку — состояние «Пустое» экрана `/` пользователь после
этого больше не увидит, пока не удалит все проекты снова.

**2. Момент экспорта файла.** Экспорт должен ощущаться мгновенным и не
пугать пользователя переходом на другую страницу. Клик по «Скачать сайт» не
меняет URL и не перезагружает редактор — браузер просто предлагает сохранить
файл (стандартное поведение `<a download>`/Blob). Кнопка на 1.5 секунды
меняет подпись на «Готово ✓», параллельно появляется тост с точным именем
файла («Готово! Файл «кофейня-atmosfera.html» скачан.»), чтобы пользователь
понимал, что именно и куда сохранилось, даже если браузер не показал
собственное уведомление о загрузке. Если экспорт недоступен, кнопка визуально
неактивна заранее (не даёт кликнуть впустую) — тост-ошибка «Добавьте секцию
Hero перед экспортом» существует только как подстраховка на случай гонки
состояний, а не как основной сценарий.

**3. Переключение темы во время правки текста.** Пользователь печатает в
поле «Заголовок» одной из секций и, не завершив ввод, переключает тему
оформления сайта во вкладке «Настройки». Переключение темы обязано влиять
только на CSS-переменные кадра предпросмотра (цвета, шрифты) и не имеет
права перерисовывать или размонтировать поле ввода, в котором находится
курсор пользователя, — фокус, позиция курсора и уже набранные, но ещё не
сохранённые символы должны сохраниться без изменений. Аналогично на
мобильном: если пользователь печатает текст на вкладке «Правка» и переключает
внутреннюю под-вкладку («Секции» → «Настройки» и обратно) или основной
сегмент («Правка» → «Просмотр» → «Правка»), значение поля должно быть уже
записано в состояние проекта на каждое нажатие клавиши (а не только по
`onBlur`), чтобы возврат на форму редактирования секции показывал текст
именно таким, каким его оставил пользователь, без потери последних символов.

## Отчёт для оркестратора

Экранов: 3 маршрутных (Стартовый список, Мастер создания, Редактор +
предпросмотр) и 4 оверлея (Библиотека блоков, Удалить секцию, Удалить
проект, Перегенерировать все тексты).

Самый сложный поток — работа с редактором на мобильной раскладке (375): один
экран должен вместить и панель управления, и живой предпросмотр через
сегмент-переключатель «Правка/Просмотр», при этом состояние текстовых полей и
предпросмотр обязаны оставаться синхронными и не теряться при переключениях
табов/сегментов, а сам кадр предпросмотра — не создавать горизонтальную
прокрутку даже в режиме «Десктоп»-viewport внутри 375px экрана.

Особое внимание фронтендера: (1) поле ввода текста секции должно писать в
общее состояние проекта на каждое нажатие клавиши, а не на `onBlur` — иначе
переключение вкладок/сегментов или смена темы посреди ввода потеряет
непереданные символы; (2) масштабирование кадра предпросмотра при выборе
«Десктоп»/«Планшет» viewport на экране 375px нужно делать через
`transform: scale` в обёртке с `overflow: hidden`, а не через изменение
реальной ширины блока, иначе появится горизонтальная прокрутка всей страницы
приложения.
