# clean-square-site

Команда из десяти ИИ-агентов для Claude Code, которая собирает приложение
целиком из одной фразы: от техзадания до проверенной сборки.

## Как пользоваться

Напиши одну фразу с идеей приложения, например:

```
Собери приложение для учёта личных расходов
```

Оркестратор проведёт работу через весь конвейер и вернёт готовый проект.
Запустить конвейер явно можно командой `/build-app`.

## Кто входит в команду

| Шаг | Агент | Отвечает за |
| --- | --- | --- |
| 1 | `product-analyst` | Техзадание, функции MVP, критерии приёмки |
| 2 | `ux-designer` | Экраны, потоки, тексты интерфейса, состояния |
| 3 | `ui-designer` | Палитра, типографика, токены, тёмная тема |
| 4 | `solution-architect` | Стек, структура папок, контракты API, скелет |
| 5 | `backend-engineer` | Маршруты, логика, данные, валидация |
| 6 | `frontend-engineer` | Интерфейс, подключение к API, адаптивность |
| 7 | `integration-engineer` | Сшивка половин, удаление заглушек |
| 8 | `qa-engineer` | Тесты, проход по критериям приёмки, починка дефектов |
| 9 | `security-auditor` | Уязвимости и производительность |
| 10 | `release-engineer` | Сборка, развёртывание, README, приёмка с чистого клона |

Шаги 5 и 6 идут параллельно, остальные последовательно.

## Как агенты передают работу

Каждый агент запускается с чистой памятью, поэтому обмен идёт только через файлы:

```
docs/01-spec.md          техзадание
docs/02-ux.md            карта экранов и потоки
docs/03-design-system.md палитра и компоненты
docs/04-architecture.md  стек, контракты API, схема данных
docs/07-integration.md   отчёт о сквозных сценариях
docs/08-qa.md            чеклист тестирования
docs/09-audit.md         находки аудита
docs/10-release.md       вердикт приёмки
```

## Правила, общие для всех агентов

- Пользователя не переспрашивают: неясности закрываются допущениями и записываются в ТЗ.
- Заглушек и незакрытых `TODO` на пути пользователя не остаётся.
- У каждого экрана есть пустое состояние, загрузка, ошибка и тёмная тема.
- Работа считается сделанной только после фактической проверки: сборка, тесты,
  ручной проход сценария.
- О том, что не получилось, сообщается прямо, а не заминается.
